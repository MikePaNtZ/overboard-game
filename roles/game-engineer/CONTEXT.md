## ⚠️ Why this file is HERE and not in `overboard/roles/game-engineer/`

Every other role's standing context lives at `overboard/roles/<role>/CONTEXT.md`, and the Notion
teardown block points there. **This role has no such directory, and creating one would be
trespassing:** `.github/CODEOWNERS` in `overboard` gives `/roles/` to the COO, and the block that
grants each role its own subdirectory does not list Game Engineer. The file's own comment is
explicit about what that means — *"A role missing from this block does not own its own context
file: it falls through to `/roles/` above, which is the COO's"* — and records that the Archivist
hit exactly this and had its own context file refused by the turf check (#90).

That is consistent with `ROLES.md`, which says this role **owns nothing in `overboard` by design**.
So the context lives in the repo the role does own, end to end.

**Filed with the COO** so a successor pointed at the `overboard` path is redirected rather than
finding nothing. Until that lands, the path above is the one that exists.

## In flight / blocked

**Blocked on `overboard#216` — the loss-of-authority warning is not on the wire.** This is the one
open dependency and it is one line of Senior Controls' code.

`sim-host` computes `authority_warning` every cycle (`host.rs:1607`) and its only two consumers
are an `eprintln!` and the trace CSV. `StateOut.flags` carries armed/valid/fallen and nothing
else. `overboard-game#19` was filed on the assumption the value "arrives over the existing state
stream" — **it does not**, and that is why the warning had never reached a player.

Everything downstream is done and measured (#21). Until the bit lands, `EStateFlags::
AuthorityWarning` reads 0 on every real packet and the banner never fires against the real host.
**ADR-0011 condition 3 cannot be closed by this repo alone.**

**`OB_City`'s drivable surface is unmeasured**, and the gate says so on every run. To clear it:
trace the road along the drivable path from `OB_BoardOrigin` and replace the `external` surface in
`terrain/levels/OB_City.terrain` with a measured `probe` series. Everything needed to consume that
data exists; only the measurement is missing. Until then the level fails
`terraincheck --strict` and carries a permanent on-screen `TERRAIN UNVERIFIED` tag.

## Dead ends and traps, worth not repeating

- **`UnrealEditor <project> OB_Main -game` silently does nothing useful.** The map must be the full
  package path: `/Game/Maps/OB_Main`. The short form starts the process, writes no log, and exits
  after ~75 s looking like a hang. Cost ~15 minutes.
- **`screencapture` needs macOS Screen Recording permission** this environment does not have; it
  fails silently under `2>/dev/null`. Use `-ObAuthorityShot`, which requests the shot from inside
  the draw call, so the captured frame is provably the right one.
- **Never pace a UDP sender with `sleep_for()` in a loop.** The first `--authority-cliff` delivered
  **~8 Hz**, not 50 — macOS sleep granularity compounding every iteration. This is the defect
  `overboard#191` fixed, and it is the reason ADR-0011's instability went unnoticed for two days:
  the same bug straddled the host's 100 ms staleness cutoff and **masked** it. Pace against an
  absolute origin and report the achieved rate.
- **Asset loads in this repo fail silently and have twice cost days** (#12's null flat material,
  #18's class-resolution fallbacks). Anything that could be null gets logged loudly on failure.
  This is why the HUD is native C++ with no `.uasset`: a safety annunciation behind a hand-authored
  widget is the one element that could go missing without anybody noticing.
- **`FObjectFinder` asserts outside a constructor.** Use `LoadObject` in `BeginPlay`. Marking it
  `static` does not save it.
- **`GetMapName()` carries a PIE prefix** (`UEDPIE_0_OB_City`). Strip it with
  `UWorld::RemovePIEPrefix` or every editor run reports an unknown level.
